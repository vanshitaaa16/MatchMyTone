# MatchMyTone - Complete Project Documentation

## Project Overview

MatchMyTone is a comprehensive personal styling and beauty analysis mobile application built with React Native and Expo, designed to help users discover their ideal color palette, understand their unique skin characteristics, and receive personalized styling recommendations. The application combines cutting-edge color analysis technology with detailed questionnaire-based assessments to provide users with actionable insights about their personal style, skincare needs, body shape, and facial structure. The platform operates on a client-server architecture where a React Native mobile app communicates with a Flask-based REST API backend, which manages user authentication, stores quiz results, and processes analysis data. The entire system is designed to be user-friendly, visually appealing, and scientifically grounded, helping individuals make informed decisions about clothing, makeup, and skincare products that enhance their natural features and boost their confidence.

## Technology Stack

The frontend of MatchMyTone is built using React Native 0.81.5 with Expo SDK 54, leveraging the Expo Router framework for file-based navigation, which provides a seamless and intuitive routing system similar to Next.js. The application uses React 19.1.0 for component management and state handling, with React Native's core components like View, Text, ScrollView, TouchableOpacity, and Modal for building the user interface. For styling, the app utilizes StyleSheet API for creating responsive layouts that adapt to different screen sizes, and incorporates Expo Linear Gradient for creating beautiful gradient backgrounds throughout the application. The Expo Vector Icons library (specifically Ionicons) provides a comprehensive set of icons for navigation, actions, and visual indicators. For data persistence on the client side, the application uses React Native AsyncStorage to store authentication tokens and user session data locally, ensuring users remain logged in even after closing the app. The frontend communicates with the backend through a custom API layer built using JavaScript's native Fetch API, with proper error handling, timeout management, and request/response logging for debugging purposes.

The backend infrastructure is built using Flask 3.0.0, a lightweight and flexible Python web framework that provides excellent flexibility for building RESTful APIs. The application uses Flask-SQLAlchemy 3.1.1 as the Object-Relational Mapping (ORM) tool, which abstracts database operations and allows for easy database schema management and query building. PostgreSQL serves as the primary database system, storing user accounts, quiz results, and all application data in a structured and relational format. For authentication and security, the backend implements Flask-JWT-Extended 4.6.0, which generates JSON Web Tokens (JWT) that expire after 30 days, providing secure stateless authentication without requiring server-side session storage. Password security is handled by Flask-Bcrypt 1.0.1, which hashes user passwords using the bcrypt algorithm before storing them in the database, ensuring that even if the database is compromised, passwords cannot be easily recovered. For email functionality, Flask-Mail 0.10.0 is integrated to send verification emails using SMTP, specifically configured to work with Gmail's SMTP servers. Cross-Origin Resource Sharing (CORS) is enabled through Flask-CORS 4.0.0 to allow the mobile app to make API requests from different origins during development. The backend uses Python's built-in `secrets` module for generating cryptographically secure random tokens for email verification, and `urllib.parse` for properly encoding and decoding URL parameters to ensure tokens work correctly in email links.

## Application Flow and User Journey

The user journey begins at the landing screen (`app/index.js`), which serves as the entry point of the application. This screen features an animated and visually engaging interface with floating sticker animations that move across the screen, creating a dynamic and modern user experience. The landing screen presents two primary authentication options: Register and Login, displayed as animated buttons that scale up when pressed, providing tactile feedback to users. When a user chooses to register, they are presented with a modal dialog that collects essential information including username, email address, phone number, and password. The registration process is handled by the `authAPI.register()` function in `src/api.js`, which makes a POST request to `/api/auth/register` endpoint on the Flask backend. The backend receives this data, validates that the username, email, and phone number are unique (using database constraints), hashes the password using bcrypt, and creates a new user record in the PostgreSQL database with `email_verified` set to `False`. Immediately after registration, the backend generates a 32-character cryptographically secure verification token using Python's `secrets` module, stores this token in the database with an expiration time of 7 days, and sends a beautifully formatted HTML email to the user's registered email address using Flask-Mail. The email contains a verification link that, when clicked, opens in the user's mobile browser and calls the `/api/auth/verify-email` endpoint, which validates the token, marks the email as verified, and displays a clean HTML confirmation page.

If a user attempts to log in before verifying their email, the backend returns a 403 status code with a JSON response containing the user ID and an error message. The frontend's login error handler in `src/api.js` detects this specific error, extracts the user ID from the response, and automatically displays an email verification modal (`showEmailVerification` state in `app/index.js`). This modal features a large white envelope icon (80px), clear instructions about email verification, the user's email address, and a "Resend Verification Email" button that calls the `/api/auth/resend-verification` endpoint to generate and send a new verification token. Once the email is verified, users can successfully log in, and the backend returns a JWT token along with user data. The frontend stores this JWT token in AsyncStorage and navigates the user to the home screen (`app/home.js`), which serves as the main dashboard displaying four analysis options: Color Analysis, Skincare Analysis, Body Analysis, and Face Analysis, each presented as an interactive card with an icon, title, and descriptive subtitle.

The Color Analysis feature (`app/ColorAnalysis/`) is a sophisticated selfie-based analysis system that helps users determine their ideal color palette. The flow begins at the Color Analysis index screen, which redirects to the Selfie Screen (`app/ColorAnalysis/screens/SelfieScreen.js`). This screen features a cream-colored background (#FFF8E7) with subtle grid lines creating a soft, elegant aesthetic. The screen displays instructions that rotate every 2 seconds using React's `useState` and `useEffect` hooks combined with `Animated.timing` for smooth fade and slide transitions. The instructions guide users to stand in good light, remove glasses and makeup, and keep their face straight. When the user taps the "Take a selfie" button, they are navigated to the camera screen (`app/ColorAnalysis/camera.js`), which is currently implemented as a placeholder that displays a "Camera Temporarily Disabled" message with a camera-off icon. The camera functionality was previously implemented using `expo-camera` and `expo-face-detector` for real-time face detection with FaceID-style validation, but has been temporarily disabled to focus on other features. Once a photo is captured (when the camera is re-enabled), the image would be processed, analyzed for skin tone, undertones, and color characteristics, and the results would be displayed on the Result Screen (`app/ColorAnalysis/screens/ResultScreen.js`), which shows personalized color recommendations, seasonal color analysis (Spring, Summer, Autumn, Winter), and specific color palettes that complement the user's natural features.

The Skincare Analysis (`app/SkincareAnalysis/`) is a comprehensive questionnaire-based assessment that evaluates various aspects of the user's skin to provide personalized skincare recommendations. The quiz system begins at the index screen, which navigates to the Quiz Screen (`app/SkincareAnalysis/screens/QuizScreen.js`). This screen implements a sophisticated quiz interface using React state management to track the current question index, store user answers in an object, and manage animations for smooth transitions between questions. The questions are loaded from a data file (`app/SkincareAnalysis/_data/questions.js`) and are shuffled using a custom `shuffleArray` function to randomize the order for each user, ensuring that users don't memorize answer patterns. The quiz interface features a progress bar at the top that animates using `Animated.timing` to show completion percentage, a question counter displaying "X/Total" questions, and a card-based layout with fade animations when selecting answers. Each question presents multiple choice options displayed as touchable buttons with active opacity effects for visual feedback. When a user selects an answer, the `handleSelect` function updates the answers state object, triggers a fade animation sequence, and automatically advances to the next question after a 180ms delay. When the final question is answered, the app navigates to the Result Screen (`app/SkincareAnalysis/screens/ResultScreen.js`) with the complete answers object passed as route parameters. The Result Screen processes these answers using a calculation algorithm that analyzes responses across different categories (skin type, sensitivity, concerns, goals), determines the user's skin profile, and displays personalized recommendations including skin type classification (oily, dry, combination, normal, sensitive), product recommendations, and a detailed skincare routine. The results are then saved to the backend database by calling `quizAPI.saveSkincareResult()` which makes a POST request to `/api/quiz/skincare`, storing the answers and calculated result in JSON format in the `quiz_results` table.

The Body Shape Analysis (`app/BodyShapeQuizNew/`) follows a similar quiz-based pattern but focuses on understanding the user's body proportions and structure to provide styling recommendations. The quiz questions are stored in `app/BodyShapeQuizNew/data/questions.js` and cover aspects such as shoulder width, waist definition, hip width, and overall body proportions. The Quiz Screen (`app/BodyShapeQuizNew/screens/QuizScreen.js`) uses the same interactive quiz interface pattern with progress tracking, animated transitions, and answer collection. The Result Screen (`app/BodyShapeQuizNew/screens/ResultScreen.js`) analyzes the answers to determine the user's body shape category (such as hourglass, pear, apple, rectangle, inverted triangle), provides detailed explanations of their body type, and offers specific styling advice including clothing recommendations, fit suggestions, and fashion tips that enhance their natural silhouette. The results are saved via `quizAPI.saveBodyShapeResult()` to `/api/quiz/body-shape` endpoint.

The Face Shape Analysis (`app/FaceShapeNew/`) is another quiz-based assessment that helps users understand their facial structure. The quiz questions in `app/FaceShapeNew/data/questions.js` focus on facial features such as jawline shape, cheekbone prominence, forehead width, and face length. The Quiz Screen and Result Screen follow the same pattern as other quizzes, with the Result Screen (`app/FaceShapeNew/screens/ResultScreen.js`) determining the face shape category (oval, round, square, heart, diamond, oblong) and providing recommendations for hairstyles, glasses, makeup techniques, and accessories that complement the user's facial structure. Results are saved to `/api/quiz/face-shape` endpoint.

The Dashboard screen (`app/dashboard.js`) serves as a central hub where users can view all their completed analysis results in one place. When the screen loads, it calls `quizAPI.getAllResults()` which makes a GET request to `/api/quiz/results`, retrieving all quiz results for the authenticated user from the backend. The dashboard displays cards for each analysis type (Skincare, Body Shape, Face Shape, Color Analysis), showing whether the user has completed each analysis and displaying the result if available. Each card is interactive, and when tapped, navigates the user to the appropriate result screen with the stored data. The dashboard uses `useFocusEffect` hook to automatically refresh results when the screen comes into focus, ensuring that newly completed quizzes are immediately visible. The screen features a gradient background using Expo Linear Gradient for visual appeal, and implements loading states and error handling to provide a smooth user experience.

The Profile screen (`app/profile.js`) allows users to view and manage their account information. When loaded, it calls `profileAPI.getProfile()` which makes a GET request to `/api/users/profile` with the JWT token in the Authorization header. The backend validates the token, retrieves the user's data from the database, and returns it in JSON format. The profile screen displays user information including name, email, phone number, gender, date of birth, and age in a clean, organized layout. The screen includes an "Edit Profile" button that navigates to the Edit Profile screen (`app/editprofile.js`), where users can update their information. The Edit Profile screen provides form inputs for each field, uses React Native's DateTimePicker for date selection, and calls `profileAPI.updateProfile()` to send a PUT request to `/api/users/profile` with the updated data. The backend validates the updates, ensures email and phone uniqueness if changed, and updates the database record. The profile screen also includes a logout button that calls `authAPI.logout()`, which removes the JWT token from AsyncStorage and navigates the user back to the landing screen.

## Backend Architecture and API Design

The backend architecture follows RESTful principles with clear separation of concerns. The main application file (`backend/app.py`) initializes the Flask app, configures database connections using environment variables from a `.env` file, sets up CORS to allow cross-origin requests, and registers all API routes. The database models are defined in `backend/models.py` using SQLAlchemy, with two primary models: the `User` model representing user accounts with fields for authentication, profile information, and email verification status, and the `QuizResult` model representing stored quiz results with a JSON field for answers and a string field for the calculated result. The database uses a unique constraint on the combination of `user_id` and `quiz_type` to ensure each user can only have one result per quiz type, with the ability to update existing results.

The authentication endpoints (`/api/auth/register`, `/api/auth/login`) handle user registration and login with proper validation, error handling, and security measures. The registration endpoint checks for duplicate usernames, emails, and phone numbers using database unique constraints, hashes passwords before storage, generates verification tokens, sends verification emails, and returns appropriate success or error responses. The login endpoint validates credentials using bcrypt password comparison, checks email verification status, generates JWT tokens with 30-day expiration, and returns user data along with the token. The email verification endpoints (`/api/auth/verify-email`, `/api/auth/resend-verification`) handle the email verification workflow, with the verify endpoint accepting tokens from email links, validating them against the database, checking expiration, and returning HTML pages for user feedback. The resend endpoint generates new tokens and sends fresh verification emails.

The quiz endpoints (`/api/quiz/skincare`, `/api/quiz/body-shape`, `/api/quiz/face-shape`) accept POST requests with quiz answers and calculated results, validate the JWT token to identify the user, and either create new quiz result records or update existing ones in the database. The `/api/quiz/results` endpoint retrieves all quiz results for the authenticated user, organizing them by quiz type and returning them in a structured JSON format. The profile endpoints (`/api/users/profile`) handle GET and PUT requests for retrieving and updating user profile information, with proper validation and error handling.

All API endpoints implement comprehensive error handling, returning appropriate HTTP status codes (200 for success, 400 for bad requests, 401 for unauthorized, 403 for forbidden, 404 for not found, 500 for server errors) and descriptive error messages. The backend uses SQLAlchemy sessions for database transactions, with proper rollback handling in case of errors, ensuring data integrity. The application logs important events like email sending, token verification attempts, and API requests for debugging and monitoring purposes.

## Testing and Quality Assurance

Testing the MatchMyTone application involves multiple layers of validation to ensure functionality, security, and user experience. For the authentication system, testing begins with user registration where testers create new accounts with various email formats, usernames, and passwords to verify validation rules, duplicate detection, and password hashing. The email verification flow is tested by registering accounts, checking email inboxes for verification messages, clicking verification links, and verifying that the HTML pages display correctly in mobile browsers. Login testing involves attempting to log in with unverified accounts to confirm the verification modal appears, testing with incorrect credentials to verify error handling, and testing successful logins to ensure JWT tokens are generated and stored correctly. The resend verification functionality is tested by clicking the resend button multiple times and verifying that new tokens are generated and emails are sent.

For the quiz systems, testing involves completing each quiz type (Skincare, Body Shape, Face Shape) with various answer combinations to verify that the calculation algorithms produce appropriate results. Testers verify that progress bars update correctly, animations work smoothly, and navigation between questions is seamless. The result screens are tested to ensure they display calculated results accurately, show appropriate recommendations, and save data to the backend correctly. The dashboard is tested by completing multiple quizzes and verifying that all results appear correctly, that tapping result cards navigates to the appropriate screens, and that the refresh functionality works when returning to the dashboard.

The profile management system is tested by viewing profile information, editing various fields, verifying that updates are saved correctly, and testing the logout functionality to ensure tokens are cleared and users are redirected appropriately. Network error handling is tested by simulating network failures, timeout scenarios, and server errors to ensure the application handles these gracefully with appropriate error messages and user feedback.

Backend API testing involves using tools like Postman or curl to send requests directly to endpoints, verifying request validation, authentication requirements, error responses, and data persistence. Database testing ensures that user records are created correctly, quiz results are stored with proper relationships, and data integrity constraints are enforced. Email functionality is tested by verifying that emails are sent successfully, contain correct verification links, and that the SMTP configuration works properly with Gmail's servers.

Performance testing involves measuring app startup time, screen transition speeds, API response times, and database query performance. The application is tested on different Android devices with varying screen sizes and Android versions to ensure responsive design and compatibility. Security testing includes verifying that passwords are properly hashed, JWT tokens are validated correctly, email verification tokens cannot be reused, and that sensitive data is not exposed in API responses or client-side storage.

## Deployment and Production Considerations

For production deployment, the backend would typically be hosted on a cloud platform like Heroku, AWS, or DigitalOcean, with the PostgreSQL database hosted separately using services like AWS RDS, Heroku Postgres, or managed database solutions. The Flask application would need to be configured with production-grade settings including proper secret keys, database connection pooling, and error logging. The frontend React Native application can be built for production using Expo's build service (`expo build:android` or `expo build:ios`) to create standalone APK or IPA files that can be distributed through app stores. Environment variables would need to be configured for production API URLs, database connections, and email service credentials. The application would benefit from implementing rate limiting on API endpoints, adding comprehensive logging and monitoring, setting up automated backups for the database, and implementing proper error tracking services like Sentry for production error monitoring.
